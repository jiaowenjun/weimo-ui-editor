## 历史修正：键盘弹出时的顶部漂移（2026-10-25）

实机证据：`录屏2026-10-25 16.09.13.mov` 中原 WdfView 唤起键盘时标题栏保持稳定；`录屏2026-10-25 16.11.34.mov` 中新方案的整张面板上移，标题栏越出可见顶部，随后随键盘收起回到原位。不是单纯的正文内部滚动。第二段来自已滚动的长对比页，Safari 底部浏览器栏也处于不同状态，不能仅凭两个页面的表现认定组件使用了不同的移动端动画。

当前源码中 A / B 窄屏直接渲染原 WdfView，数据适配层不控制焦点和几何。两者共用的视口跟随存在两处可复现缺口：只监听 resize，忽略不伴随尺寸变化的 visualViewport.scroll；resize 更新的 top / left 又参与 320ms 过渡。可视区域发生平移时，缺失或延迟的位置补偿都会使卡片离开顶部边距。录屏现象与此路径吻合；实机当时的 offsetTop / scrollY 未采集，因此“长页面及浏览器栏状态触发视口平移”仍是待同机数据确认的触发条件。

修正范围：

- WdfView 和 A / B 共用视口监听，同时响应 resize 与 scroll。窄屏稳定编辑态的位置即时补偿，保持 `top - visualViewport.offsetTop = 12px`；纯平移只写 top / left，不改高度、不重启高度过渡。
- 窄屏稳定编辑态只保留宽高过渡。展开、关闭和桌面面板继续原来的四属性过渡，宽屏 flow / snapshot 逻辑不变。
- 连续 resize 只保留最后一个清理计时器；关闭、过期会话和卸载不再接受视口更新，清理不会移除关闭动画正在使用的类。
- 继续不自动聚焦；没有新增主动滚页、固定 body、额外定位层或原生 dialog。

验证结果：22 项聚焦测试通过，含 7 项新增视口事件顺序、纯平移、连续 resize、清理和 CSS 范围回归。库编译与 CSS 产物、类型检查、原 WdfView 行为契约、站点模板契约、站点生产构建和差异格式检查通过。

在桌面 Chromium 的 390 × 844 窄屏页中，向真实面板监听注入事件：A 的 viewport height=460、offsetTop=0/24/64/96/72/0；B 的 height=460、offsetTop=0/96/48/0；原 WdfView 单独检查 offsetTop=96 的纯 scroll。三者的渲染 top 都即时补偿，计算可见顶部间距始终为 12px；A / B 的 transition-property 为 width,height。测试后已恢复原视口属性。原组件 opening / closing 仍为 top,left,width,height。A 取消、B 保存均回到阅读态并解除锁页，没有自动聚焦正文。

宽屏 1100 × 900 复核：A 的卡片从约 302px 收到 254px，工具栏由 48px 收到 0 且观察到中间高度；B 仍运行浏览器转场，保存后回到阅读态。页面未记录新的 warn/error。帧采样只证明存在过渡，不代表实机呈现帧率。

**实机结论仍待复验。** 上述事件注入验证了监听与 CSS 的实际组合，不是 iOS 键盘模拟。尝试连接设备时，Xcode 工具尚未授权，Safari 开发菜单中的 iPhone 停在“正在连接”，未获得可用的实机调试会话。请在原长对比页中分别测试 A / B，重点覆盖先向下滚动使浏览器栏收起、再展开卡片并手动点击正文的路径，以及键盘收起后退出。

## 前一轮：窄屏复用原组件（2026-10-25）

按本轮要求，窄屏两方案直接使用原 WdfView，而不是继续修补实验面板。原组件的 DOM、CSS、Popover 提层、320ms 开合、编辑器就绪等待、视口和焦点处理、180ms 键盘等待、退出 Ghost 交接全部共用同一份代码；没有复制出另一套移动端样式或时序。原 WdfView 的外部 API 不变。

- ≤640px 时，auto / inline / dialog 都选择原面板；宽屏 auto / inline 保留原来的 flow / snapshot 实验，显式 dialog 也使用原面板。编辑会话期间跨断点不替换组件，关闭后再适配。
- NewMdfView 的 WDF 文档和异步 onCommit 由内部数据适配层衔接，仍然先保存成功再关闭、失败保留草稿、取消不提交、卸载忽略迟到结果。原 WdfView 未使用该适配层时继续原保存语义。
- 原生 dialog 实验、独立视口变量、独立锁页和 240ms 面板动画已移除。宽屏原位动画的 flow / snapshot 实现保留。
- 此次只做源代码、数据和构建检查；未重新进行浏览器渲染或 iPhone 实机验证。此前的 16px 面板边距、812px 高度等实验测量不适用于当前原组件面板。

当时检查结果：15 项聚焦测试通过，覆盖窄屏强制原面板、会话跨断点冻结、原组件唯一渲染路径、宽屏动画保留、原退出时序和保存适配。类型检查、原 WdfView 行为契约、站点模板契约、库/站点构建、包导出检查和差异格式检查通过。逐段比较确认原展开、关闭、settle 编排及两种内联动画函数均保持不变；该轮尚未修改原移动端辅助模块和 CSS，当前视口补偿变更见上一节。

实机重点：刷新后 A / B 都显示原组件顶部保存/取消按钮；手动唤起键盘、长文滚动、保存/取消、页面顶部/中部/底部落位与原 WdfView 一致。再在宽屏检查 A / B 内联动画没有变化。

## 历史验证：双方案阶段

环境为桌面 Chromium 155,分别检查宽屏及 390 × 844 窄屏尺寸。窄屏尺寸不等于 iPhone 实机。

- 方案 A：退出时操作区高度逐步从 48 降至 0,卡片底边与下方参照内容同步移动,结束后没有额外高度变化。
- 方案 B：浏览器显示的转场卡片从约 302 连续收拢到约 254,不是只淡出按钮。
- 原位保存和取消都能返回阅读;取消不增加成功提交次数。
- 等待保存时操作禁用;保存失败保留草稿,改为成功后可重试,只计一次成功提交。
- 窄屏自动进入面板;长文独立滚动,操作区位于可用区域内。退出后恢复背景交互,焦点回到编辑入口。
- 修改内容后取消,返回原正文及其最终阅读高度;退出过程中操作区连续收拢。
- 空内容进入再退出后,正文占用高度保持一致。
- 已取消的草稿不能通过下一次编辑中的撤销操作恢复。
- 最终浏览器验证过程未出现新的运行警告。

聚焦检查：9 项新增测试、组件类型检查、原 WdfView 行为检查、站点模板检查、包导出检查、站点生产构建及差异格式检查通过。自动检查不代表实机动画通过。

## Safari 键盘回归与修复

2026-10-24 的实机录屏 `ScreenRecording_10-24-2026 15-15-32_1.mp4` 显示：打开编辑后立即出现光标和软件键盘，卡片先向下展开，再突然跳到键盘上方。用户确认 A / B 都有位置漂移和闪烁，因此此前窄屏 Chromium 结果不能作为移动 Safari 验收结论。

源码复核发现，两个方案共用面板路径：展开过程中主动聚焦正文，同时面板动画使用已经捕获的终点，而键盘视口监听仍在更新居中位置。固定 body 和视口滚动跟随也与原 WdfView 的默认路径不同。录屏不能单独证明 Safari 合成闪烁的全部原因；本轮针对已确认的焦点与几何竞争修复。

- 所有编辑入口均不自动聚焦正文。原生面板打开前，将初始焦点明确指向非输入标题，避免浏览器自行选择正文。点击正文仍能正常输入。
- 窄屏面板顶部对齐；键盘压缩可用空间时限制正文滚动区域，操作区保持可达。
- 视口尺寸变化合并到一帧处理，变化前取消旧的展开几何动画；不再用视口滚动事件反复重新居中。键盘恢复后停止监听，再交给返回动画，避免解锁背景时争用几何。
- 背景沿用原组件的 overflow 锁定与滚动条补偿，不再将 body 改成 fixed；退出恢复原样式和必要的滚动位置。原 WdfView 未修改。

本轮桌面 Chromium 窄屏复核：A / B 初始焦点均在非输入标题；原位模式也不自动进入正文。手动聚焦后，将可用尺寸从 390 × 844 缩到 390 × 460，普通卡片顶部保持 16px；长文面板高度从 812px 收缩为 428px，操作区底部为 443px，仍在可用范围内。取消和保存后恢复阅读、焦点入口和背景样式；长文返回前后页面 scrollY 同为 2989。上述尺寸变化不是 iOS 软件键盘实机仿真。

新增焦点策略、原生初始焦点、滚动锁恢复、视口变更中断与清理、退出交接检查，现有 14 项测试全部通过；类型检查、原 WdfView 行为检查、站点模板检查、站点生产构建和差异格式检查通过。最终浏览器取消返回检查正常，未记录到 warn/error。修复后的 iPhone Safari 零闪烁结论仍待同机复验，不能由单元测试或 Chromium 替代。

## 待实机验收

- iPhone Safari 首次进入和再次进入均不自动弹出键盘；点击正文才开始输入。
- 展开尚未结束时立即点击正文、长文末尾输入、键盘收起后返回，均无闪烁或反向跳动。
- 页面顶部、中部、底部的滚动位置,尤其是长文大量增删后返回。
- 键盘展开时旋转屏幕、快速连续操作、中文输入法组合输入。
- 明暗主题和系统减少动态效果下的完整操作。
- 连续布局过渡的文字清晰度、结束帧稳定性及主观流畅度。

手机窄屏检查原组件面板和键盘；宽屏选择“原位编辑”验证连续布局过渡。方案二已移除，不再作为候选。
